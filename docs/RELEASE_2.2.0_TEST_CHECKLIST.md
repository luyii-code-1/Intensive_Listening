## 08. 积分、冻结、结算与支付（P0）

- [ ] MONEY-01：Desktop ASR 按服务器时长 `ceil(秒数/60) × 0.5` 计费；60 秒 0.5、略超 60 秒 1、120 秒 1、190 秒 2、1800 秒 15 积分。
- [ ] MONEY-02：提交 ASR 只冻结，成功只扣一次，失败/取消释放本次全部冻结；重复取 SRT 免费。
- [ ] MONEY-03：余额不足、余额刚好、其他操作占用冻结和并发消费；available=balance-held，始终无负数或超扣。

## 建议执行顺序与交叉端验收

1. 先冻结候选、完成 Windows/macOS 安装冒烟和备份，保证测试针对确定版本。
2. 优先执行 DATA、PLAY、ASR、MONEY、AUTH 的 P0，以及 MDN 更新和远程退出链路。
3. 执行制作、MCP、云后台、Web 和 UI 验收，再补异常、兼容和性能用例。
4. 每个缺陷记录复现素材和影响范围；修复后复验失败项及直接关联流程。
5. 生成最终正式候选后，执行 REL 和关键端到端冒烟，再决定发布。

必须完成的交叉端场景：

- Windows 制作 ILP → macOS 导入播放 → Web 导入播放，字幕、题目、答案、挖空一致。
- macOS 制作 ILP → Windows 导入播放；工程 ZIP 在两平台往返编辑。
- 云端制作 → 审阅完成 → Desktop 下载 → Web 在线打开；各次价格和内容版本一致。

## 发布判定

Windows 和 macOS 都应有最终候选的构建、原生运行、安装和关键主流程证据。适用 P0 全部通过，P1 完成且遗留问题经过明确评估；所有错误扣费、越权、数据丢失、核心播放失败和不可恢复任务卡死为零。真实阿里识别与账务对账至少完成一轮。备份恢复、最终下载校验和用户 UI 验收有明确结果后再正式发布。
